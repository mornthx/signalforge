## Threshold evaluation

Spec §7.4 gates:
- Simple schema (4–6 numeric fields): **≥ 100 000 frames/sec**.
- Complex schema (bit fields + scale/offset + fixed_string):
  **≥ 50 000 frames/sec**.

| Scenario | Frames/sec | Signals/sec | Target | Headroom |
|---|---|---|---|---|
| Simple (4 numeric + magic + padding = 5 fields) | **410 768** | 2 053 839 | 100 000 | **4.1×** |
| Complex (scale+offset_transform numeric + 4-slice bitfield + float32 + fixed_string + padding = 10 signals) | **398 250** | 3 982 497 | 50 000 | **8.0×** |

Verdict: ✓ **pass**, no HALT.

## Sanity checks

- Both scenarios decode every frame without producing unmatched or
  malformed warnings (the schemas exactly match the synthetic
  payloads).
- Signals-per-second ratio is consistent with the schema declarations:
  - Simple: 5 signals × 410 768 fps ≈ 2.05 M signals/sec
  - Complex: 10 signals × 398 250 fps ≈ 3.98 M signals/sec
- The complex schema achieves nearly the same throughput as simple
  despite emitting twice the signals; per-signal cost dominates and
  is dominated by `SignalValue` variant construction + std::shared_ptr
  sink hop, not bitfield/scale/string extraction.

## §5.5 categorization

Both scenarios pass their absolute targets; no §5.5 mitigation
needed. The benchmark measures **inline decode cost only** — adding
a real `FramePipeline` + `MockDriver` source thread (the real
production path) would introduce M4-grade pipeline overhead (~4.5 %
per `M4-baseline.md`), which is well within the ample headroom.

## Reproduction

```
cmake --preset=release -DSIGNALFORGE_BENCHMARKS=ON
cmake --build --preset=release --target bench_decoder_throughput
./build/release/tests/benchmark/bench_decoder_throughput
```

Exit code 0 indicates the verdict is `within_threshold`; non-zero
indicates a HALT-trigger condition (one or both scenarios below
target).

## Observations

- The decoder hot path uses no per-frame allocations beyond the
  `SignalValue` variant construction (which uses small-object
  optimization for bool / int64 / double; only `QString` triggers a
  ref-count touch on the implicitly-shared backing store).
- `SchemaValidator` is **not** measured by this benchmark — it runs
  once at decoder construction. Validation cost was indirectly
  observed in S4 to be microseconds for the canonical schema, well
  inside the spec §7.6 100 ms budget.
- Cross-byte bit field extraction (the `device_id` slice in the
  complex schema) does not noticeably slow the decode — same uint16
  read + shift + mask path as a within-byte slice.
