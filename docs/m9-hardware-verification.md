# M9 Manual Hardware Verification Protocol

Per M9 spec §8.3, the four driver types (Serial / TCP / UDP / Replay) are verified end-to-end against real (or hardware-equivalent) endpoints before milestone close. Automated CI cannot replace this gate — it observes the driver code path but not the integration with real device firmware.

The protocol is run **once before merge** by the responsible engineer, on a developer workstation with the hardware available. Results land in `.claude/M9-done.md §Manual hardware verification`.

---

## Pre-flight

1. Build Release locally:
   ```
   cmake --build build/release
   ```
2. Confirm the build artifact exists:
   ```
   ./build/release/src/app/signalforge --version  # not yet implemented; use --help or just launch
   ```
3. Confirm `examples/schemas/temperature_sensor.yaml` and `examples/schemas/modbus_style.yaml` are at hand for the schema combo.

---

## Test 1 — Serial driver (USB-serial dongle or socat)

**Setup**:

- Option A (real hardware): a USB-serial adapter (FT232 / CP2102) connected to a target board emitting a known frame format.
- Option B (no hardware): two-port virtual loopback via `socat`:
  ```
  socat -d -d pty,raw,echo=0 pty,raw,echo=0
  ```
  Note the two `/dev/pts/X` paths it prints. Use one as device, write a hand-rolled byte stream to the other to simulate device traffic.

**Steps**:

1. Launch SignalForge.
2. Connections → Add…
3. Driver type: Serial. Device: the `/dev/ttyUSB0` (or socat path). Baud: 115200, 8/N/1, no flow control.
4. Display name: "Serial test". Decoder schema: `temperature_sensor` (or empty for raw).
5. OK. Verify the connection appears in the connection list with state "Idle".
6. Click Connect. Verify the state transitions Idle → Connecting → Connected within ~1 sec.
7. Verify the chart's signal selector shows decoded signals (if a schema was selected).
8. Click Disconnect. Verify Idle.
9. Quit and relaunch SignalForge. Verify the connection persists.
10. Click Connect on the persisted entry. Verify it reconnects.

**Pass criteria**:
- States transition without error.
- If a schema was selected, signals appear in the selector.
- The connection is persisted across restart.

**Result row in M9-done.md**: pass / fail / N/A; observed states; any error messages.

## Test 2 — TCP driver

**Setup**:

- Either a real device exposing a TCP listener, or a local echo server:
  ```
  socat TCP-LISTEN:9090,reuseaddr,fork EXEC:'cat'
  ```

**Steps**:

1. Connections → Add…
2. Driver type: TCP. Host: `127.0.0.1`. Port: `9090`. Connect timeout: 5000.
3. Display name: "TCP test". Decoder schema: empty.
4. OK. Verify it appears in the list as "Idle".
5. Click Connect. Verify Idle → Connecting → Connected.
6. (Optional) Add an auto-connect command with payload `48656c6c6f0a` (= "Hello\n") and expected `48656c6c6f0a`. Reconnect and verify the autoConnectCommandSent log line and a Connected state remains.
7. Disconnect.

**Pass criteria**:
- States transition without error.
- Auto-connect command (if set) sends and the expected response triggers no WARN/ERROR log.

## Test 3 — UDP driver

**Setup**:

- Local UDP sender:
  ```
  echo "ping" | socat - UDP-DATAGRAM:127.0.0.1:7000
  ```
  (run from a separate terminal after the connection is up).

**Steps**:

1. Connections → Add…
2. Driver type: UDP. Local bind: `0.0.0.0`. Local port: `7000`. Remote: empty.
3. Display name: "UDP receive". Decoder schema: empty.
4. Connect. Verify Connected.
5. Run the socat sender. Verify the chart's signal selector / log shows incoming frames.
6. Disconnect.

**Pass criteria**:
- States transition.
- Incoming UDP datagrams reach the application as RawFrame (visible via SF_LOG / signal counter).

## Test 4 — Replay driver

**Setup**:

- Use any existing `.sfreplay` session file. If none is available, generate a 16-byte zero-magic placeholder (will open with no frame stream) using:
  ```
  printf 'SFREPLAY\0\0\0\0\0\0\0\0' > /tmp/empty.sfreplay
  ```
- Or for a real frame stream, use a session generated by M11's session writer (when available; M9 ships only the driver side).

**Steps**:

1. Connections → Add…
2. Driver type: Replay. File: pick the `.sfreplay`. Speed: 1.0. Loop: off.
3. Connect. Verify Connected.
4. If frames are present, verify the chart's signal selector shows decoded signals.
5. Disconnect.
6. Re-add with Speed: 0.5 (slower playback). Reconnect. Verify the file plays through over twice the original duration (within 5% per spec §8.3).

**Pass criteria**:
- States transition cleanly.
- Frame count matches file content.
- playbackSpeed scales the duration.

---

## Test 5 — Persistence across restart

**Steps**:

1. With at least one connection of each driver type configured, quit SignalForge.
2. Inspect `~/.config/signalforge/connections.yaml` (or the platform-equivalent). Verify the schema_version, the connection entries, and that any `payload` / `expected` round-trips as `!!binary`.
3. Relaunch SignalForge. Verify all configured connections appear in the list, in Idle state.
4. Click "Connect all". Verify each connects (assuming the underlying endpoints are still available).

**Pass criteria**:
- yaml file is well-formed and bit-identical to the in-memory representation after a save→load→save round-trip.
- All connections re-appear after restart.

---

## Test 6 — Error path: invalid configuration

**Steps**:

1. Connections → Add…
2. Driver type: TCP. Host: `127.0.0.1`. Port: `9999` (assumed unused).
3. Connect. Verify the state goes Connecting → Error within the configured timeout (5000 ms default).
4. Verify the connection's "lastError" message is informative (e.g., "TCP connection to 127.0.0.1:9999 timed out after 5 seconds. Verify host is reachable.").
5. Click Disconnect → Idle (recovery).

**Pass criteria**:
- Error path produces an actionable error message (per spec §10).
- Disconnect resets to Idle (recoverable).

---

## Reporting

For each test, record in `.claude/M9-done.md` under the Manual hardware verification section:

- Test number + driver type
- Result: pass / fail / N/A (and reason for N/A, e.g., "no FTDI dongle on hand; used socat virtual port")
- Observed transitions
- Any deviations from expected behavior
- Date + tester initials

Pass rate goal: 6/6. A single fail blocks merge until investigated. N/A is acceptable when the hardware is genuinely unavailable AND the equivalent automated test (in `tests/integration/`) covers the code path.
