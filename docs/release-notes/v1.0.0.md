# SignalForge v1.0.0 — Release Notes

**Release date**: 2026-05-09
**Tag**: `v1.0.0`
**Platform**: Ubuntu 24.04 amd64

---

## What is SignalForge?

A Qt desktop workbench for embedded-device bring-up. Connect to
serial / TCP / UDP data sources, decode signals via YAML
schemas, visualise them on real-time charts, derive new
signals via expressions, record sessions to a documented
binary format, and replay sessions through the same charts at
1× / 0.5× / 2× / 5× / 10× speed.

V1.0 is the first stable release. The functional surface is
locked; future feature work happens in V1.5+ (additive) or V2
(breaking).

---

## What's in V1.0

### Connect (M2 + M3 + M9)

- **Serial** (USB / RS-232) via Qt's `QSerialPort`
- **TCP** client with persistent reconnect
- **UDP** datagram-listener
- **Replay driver** (replays raw frame logs from prior runs)
- Connection manager with persistent yaml config
  (`~/.config/signalforge/connections.yaml`)
- Auto-connect on startup (per-connection setting)

### Decode (M4 + M5)

- YAML-driven schema decoder (`schema/*.yaml`)
- One frame in → multiple `SignalValue` events out
- Type-safe variants: bool / int64 / double / QString
- Optional linear scale + offset (`raw * scale + offset`)
- Cycle-detection in expression engine (no infinite loops)

### Buffer + derive (M6 + M7)

- Lock-free signal buffer with per-type storage + LOD
  pyramid for fast chart rendering
- Bounded staleness ≤ 1 ms
- Expression engine for derived signals
  (`my_signal = a * 2 + sin(b)`)
- Cycle-safe (M7 ADR-006)

### Visualise (M8)

- Real-time charts via Qt Quick + RHI
- Per-signal Y-axis, multi-signal overlay
- Time-axis presets: 1 sec / 10 sec / 1 min / 10 min / 1 hour
- Live-mode toggle (pause / resume)
- 50× margin on chart frame budget per M8 baseline

### Record (M10)

- SFREPLAY v1 binary format
  (`docs/format/sfreplay-v1.md`)
- 60 000 events/sec sustained throughput per M10 baseline
- Bounded queue with C3 4-point backpressure policy
- `sfreplay_inspect` CLI for ad-hoc file inspection

### Replay (M11 + M12)

- File → Open Session… (Ctrl+O) loads any `.sfreplay`
- Replay toolbar: Play / Pause / Step ◀▶ / Scrubber /
  Speed combo / Exit Replay
- 1× timing accuracy: **0.01 % error** (M12 deadline-based
  pacing — a 99.93 % improvement over M11 baseline)
- 10× completion: 1.11 s for a 10-second file (51 %
  improvement over M11 baseline)
- Step-backward via O(N) re-walk (V1.5+ may add an indexed
  fast-rewind)
- Live ↔ Replay mode toggle with connection-state
  preservation

## System requirements

- **OS**: Ubuntu 24.04 LTS (or compatible Debian-based
  distribution)
- **Architecture**: amd64 (x86_64)
- **Qt**: **6.10.x** — **must be installed separately**
  (newer than Ubuntu 24.04 stock Qt 6.4). The `.deb`'s
  `Depends:` field declares the Ubuntu 24.04 stock Qt 6.4
  packages to satisfy `dpkg`, but the SignalForge binary
  links against the Qt 6.10 ABI. See `install.md §1.1` for
  installation options.
- **GLIBC**: 2.38 or newer (Ubuntu 24.04 ships 2.39)
- **libstdc++**: 13 or newer (Ubuntu 24.04 ships 14)
- **yaml-cpp**: statically linked (no runtime dependency)
- Standard system libraries (libdbus-1-3, libfontconfig1,
  libfreetype6, libglib2.0-0t64, libxcb1, libxkbcommon0,
  libgl1, libegl1, libglx0, zlib1g) — all in default
  Ubuntu 24.04 repos.

For the V1.5+ multi-platform plan, see "Roadmap" below.

## Quick start (5 minutes)

1. **Connect** — Open SignalForge. Connections panel
   (left dock) → Add. Pick driver type, fill in config
   (e.g., serial port `/dev/ttyUSB0`, baud 115200,
   schema `schema/example.yaml`). Click Connect.
2. **See signals** — Signal selector (left of chart pane)
   shows decoded signals. Drag one into a chart.
3. **Record** — Session → Record… (Ctrl+R). Pick a
   `.sfreplay` filename. Status bar shows live byte count.
   Stop with the same menu.
4. **Replay** — Disconnect any live connection. File →
   Open Session… (Ctrl+O), pick the file. Replay toolbar
   appears; click Play. Charts repopulate at original
   timing.
5. **Tune** — Speed combo: try 10× to skim, 0.5× for
   detail. Step ◀▶ for record-by-record. Drag the
   timeline scrubber to jump.

## Known limitations (V1.0)

- **Linux-only**. No macOS / Windows builds for V1.0.
  Roadmap: V1.5+.
- **Qt 6.10 dependency**. Newer than Ubuntu 24.04 default;
  user must install Qt 6.10 from an external repo (see
  `install.md`).
- **No localization**. Single language (English).
  Roadmap: V1.5+.
- **No multi-file replay playlist**. One `.sfreplay` at a
  time. Roadmap: V1.5+.
- **Step-backward is O(N)**. Re-reads from start of file.
  Acceptable for files < 100 k records; may feel slow on
  larger files. Roadmap: V1.5+ in-memory index.
- **No code signing / notarisation**. The .deb is plain
  Debian. Roadmap: V1.5+.
- **No app store / repository submission**. Distribution is
  GitHub Releases only. Roadmap: V1.5+.
- **No automated release CI**. Releases are cut manually.
- **Live-mode reconnect edge case (ADR-009)**. When a
  connection cycles `Error → Idle → Connecting → Connected`
  rapidly, there is a small window where the
  PipelineManager detach/re-attach can race. Typical
  user-driven Disconnect → Connect cycles are unaffected.
  Roadmap: V1.0.1 hardening.
- **Chart theming fixed-light**. Chart background is plain
  white; line colors use light pastels. No dark-mode or
  user-configurable theme. Roadmap: V1.5+ (the ADR-010
  `ChartHost.qml` scene is the theming hook).
- **No "remove chart" button**. Charts are added via the
  `+ Chart` toolbar action; removing a chart requires
  exiting and editing the saved chart config yaml.
  Roadmap: V1.5+ UX polish.
- **Connection dialog tilde expansion**. Path fields don't
  expand `~`; users must enter absolute paths.
  Roadmap: V1.0.1 polish.
- **`SF_LOG_LEVEL=debug` ineffective in Release builds**.
  The Release build defines `SF_LOG_MIN_LEVEL=info` at
  compile time, so the env var has no effect. Workaround:
  use the Debug build for verbose diagnostics.
  Roadmap: V1.0.1 fix.
- **No GUI integration test in CI** (V1.0 governance gap).
  M13 caught three multi-milestone GUI bugs (ADR-008,
  ADR-009, ADR-010) that unit tests missed. V1.5+ adds a
  CI test that connects a mock driver, injects frames, and
  verifies chart redraw count > 0.

## Roadmap (informational only — not a commitment)

### V1.5+ (additive, no breakage)

- Multi-platform support (macOS, Windows)
- Code signing / notarisation
- Localization / i18n
- Multi-file playlist for replay
- Backward-seek indexed fast-rewind (M11 V1.5+ candidate)
- Theme / dark mode
- M6 SignalBuffer Double-specific perf optimisation
  (M12 S4 H4 finding)
- SignalBufferRegistry per-event hashtable lookup
  (M12 profile §6.6 candidate)
- Static linking of Qt for self-contained .deb

### V2 (breaking changes, separate planning cycle)

- Network sync / live streaming protocol
- Encryption / authentication on file format
- Plugin architecture
- Two-file `.sfr` + `.sfi` index design
  (M10 ADR-007 deferred)
